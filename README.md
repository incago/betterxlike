# Better X Likes

한국어 | [English](README.en.md) | [日本語](README.ja.md)

X의 **홈·검색 결과·프로필·북마크·마음에 들어요**를 **창 너비에 맞춰 한 줄에 트윗 1~4개**가 보이는 그리드로 바꾸는 Chrome 확장 프로그램입니다. 팝업에서 각 화면을 **그리드 / 기본 목록**으로 따로 선택하며, 그리드 화면의 우측 검색·트렌드·팔로우 사이드바를 숨깁니다. Manifest V3 기반이며, 빌드나 API 키 없이 설치할 수 있습니다.

## 설치

1. Chrome 주소창에서 `chrome://extensions`를 엽니다.
2. 오른쪽 위 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드합니다**를 누릅니다.
4. 다운로드하거나 복제한 프로젝트 폴더(`manifest.json`이 있는 폴더)를 선택합니다.
5. 이미 열어 놓은 X 탭을 **한 번 새로고침**합니다.
6. 로그인한 상태에서 [홈](https://x.com/home), 검색 결과, 프로필, [북마크](https://x.com/i/history) 또는 [마음에 들어요](https://x.com/i/history/likes)를 엽니다.

확장 프로그램을 툴바에 고정하면 팝업의 **그리드 사용** 스위치로 기본 목록과 그리드를 전환할 수 있습니다. 설정은 이 브라우저에 저장되며, 열린 X 탭에도 적용됩니다.

1.5.4부터 처음 설치하거나 저장된 화면 설정이 없으면 **북마크·마음에 들어요만 그리드**, **홈·검색·프로필은 기본 목록**으로 시작합니다. 기존에 저장한 화면별 선택은 업데이트 후에도 유지됩니다. 자동 테스트 59개로 기본값, 설정 보존과 그리드 전환을 확인했습니다.

## 언어

1.5.1에서 한국어·영어를 지원했고, 1.5.2에서는 일본어를 추가했습니다. 팝업 전체와 확장 프로그램 설명을 세 언어로 제공합니다. [Chrome i18n](https://developer.chrome.com/docs/extensions/reference/api/i18n)의 표준 번역 파일을 사용합니다. Chrome 인터페이스가 한국어·일본어이면 해당 언어로, 그 외에는 영어로 표시합니다. 언어가 바뀌어도 기존 화면별 설정은 유지됩니다. 일본어 표시와 설정·오류 처리를 포함한 자동 테스트 56개가 통과했습니다. X 자체 화면이나 게시물 내용을 번역하지는 않습니다. [영어 설치 안내](README.en.md), [영어 스토어 설명](store/listing-en.txt), [영어 개인정보처리방침](https://incago.github.io/better-x-likes-privacy/en.html), [일본어 설치 안내](README.ja.md), [일본어 스토어 설명](store/listing-ja.txt), [일본어 개인정보처리방침](https://incago.github.io/better-x-likes-privacy/ja.html)을 제공합니다. 프로젝트에 별도의 이용약관 문서는 없습니다.

## 동작

- 홈(`/home`), 검색(`/search`), 프로필(`/사용자명`, `/with_replies`, `/media`, `/highlights`), 북마크와 마음에 들어요의 게시물 목록에서 적용합니다. 팝업에서 각 화면의 **그리드 / 기본 목록**을 선택합니다. 프로필 설정은 내 프로필과 다른 프로필에 동일하게 적용합니다. 게시물 상세, 메시지, 알림, 탐색, 팔로워 목록과 게시물이 없는 화면은 기본 레이아웃을 유지합니다.
- 그리드를 선택한 화면에서 우측 검색·트렌드·팔로우 사이드바 전체를 숨기고 목록의 가로 공간을 넓힙니다. 왼쪽 탐색 메뉴는 유지합니다. 기본 목록을 선택하면 사이드바와 영상 동작도 복원됩니다.
- 타임라인 내부 래퍼의 너비 제한과 오른쪽 정렬을 해제해, 그리드가 콘텐츠 영역의 왼쪽부터 전체 너비를 사용합니다.
- 콘텐츠 영역이 1060px 이상이면 4열, 800~1059px이면 3열, 540~799px이면 2열, 540px 미만이면 1열로 표시합니다. 창 크기를 바꾸면 즉시 다시 배치합니다.
- 텍스트를 추가로 잘라내거나 트윗을 복제하지 않습니다. 기존 트윗 요소에 스타일을 적용하므로 X의 링크와 버튼, 미디어 요소를 유지합니다.
- 추가로 나타나는 트윗과 X 내부의 페이지 이동을 감지합니다.
- 가상 타임라인의 전체 높이와 셀의 Y 좌표는 X가 관리합니다. 행 높이를 현재 열 수로 나눠 각 트윗의 측정 높이에 적용하고 카드만 내부에서 이동해, 다음 항목을 로딩하는 스크롤 계산을 유지합니다.
- 그리드의 영상 자동재생을 막습니다. 영상 영역에서 직접 재생 버튼을 누르거나 키보드로 실행한 영상만 재생을 허용합니다. 좋아요나 게시물 텍스트를 누르는 것은 재생 요청으로 취급하지 않습니다. 그리드를 끄거나 다른 페이지로 이동하면 X의 기본 재생 동작으로 돌아갑니다.
- 라이트/다크 모드의 X 기본 색상을 따릅니다.

## 권한과 데이터

`storage` 권한은 전체 사용 스위치(`enabled`)와 다섯 화면의 그리드/기본 목록 설정(`pageModes`)을 로컬에 저장하는 데 사용합니다. 콘텐츠 스크립트는 `x.com`과 `twitter.com`에서 실행되어 홈·검색·프로필·북마크·마음에 들어요의 게시물 목록 진입을 감지합니다. 트윗 내용을 저장하거나 외부로 전송하는 별도 코드, 서버, 분석 도구는 없습니다.

## 검증과 제한

1.5.6에서는 게시물 사이에 들어오는 팔로우 추천이 그리드와 겹치는 문제를 수정했습니다. 추천 제목·계정·더 보기 링크를 그리드에서 숨기고, 가상 목록은 해당 셀을 0 높이로 측정합니다. X의 DOM과 Y 좌표를 유지하며 로딩·오류 재시도와 게시물 안의 계정 표시는 숨기지 않습니다. 기본 목록·비활성화·화면 이동 시 원래 추천을 복원합니다. 자동 테스트 62개를 통과했습니다. `/incago?virtual=1&recommendations=1`의 “추천 영역 테스트”에서 1~4열 각각 13개 항목과 42개 게시물 추가 로딩을, 일반 목록에서는 11개 항목을 통과했습니다. `&width=500/800/1000`은 각각 1/2/3열 콘텐츠 폭을 재현합니다. 실제 로그인한 X의 동작은 별도 확인이 필요합니다.

1.5.5에서는 프로필 그리드의 상단 UI가 과도하게 커지는 현상을 수정했습니다. 타임라인 경로 밖에 있는 제목·배너·프로필 사진·소개·탭의 폭을 최대 600px로 유지하고, 좁은 화면에서는 가용 폭에 맞춥니다. 게시물 목록은 전체 폭으로 1~4열을 사용합니다. 원래 프로필 요소와 클릭 동작을 유지하며 기본 목록·비활성화·화면 이동 시 스타일을 복원합니다. 자동 테스트 60개, 로컬 프로필 일반 목록 19개 항목과 가상 스크롤 16개 항목(42개 게시물)을 통과했습니다. 넓은 화면에서 배너 높이 약 200px 유지와 좁은 콘텐츠 폭에서 축소를 확인했습니다. 실제 로그인한 X의 프로필에서 별도 확인이 필요합니다.

1.5.3에서는 홈의 “게시물 보기”로 새 글을 불러올 때 첫 줄이 화면 위쪽으로 밀려 스크롤로 접근할 수 없는 문제를 수정했습니다. 새 글 앞에 음수 위치 번호를 붙이던 처리를 고쳐 화면 밖의 게시물까지 전체 순서를 다시 맞추고, X가 같은 목록을 교체하거나 맨 앞을 잘라내면 오래된 순서와 높이를 초기화합니다. X의 스크롤 좌표와 전체 목록 높이는 그대로 사용합니다.

자동 테스트 59개를 통과했습니다. `/home?virtual=1`의 “홈 갱신 테스트”에서는 새 글 1·3·35개 추가, 첫 줄 정렬, 상단 접근, 아래로 스크롤 후 복귀, 기본 목록에서 갱신 후 그리드 복원을 확인합니다. `&width=500`, `&width=800`, `&width=1000`으로 콘텐츠 폭을 제한해 1·2·3열을 재현할 수 있습니다. 로컬 브라우저에서 1~4열 각각 21개 항목, 기존 추가 로딩 16개 항목을 통과했습니다. 실제 로그인한 X의 동일 동작은 별도 확인이 필요합니다.

로컬 DOM 테스트로 페이지 진입/이탈, 설정 변경, 동적 트윗 추가, 원래 클릭 이벤트 유지, 타임라인 교체, 복원을 확인할 수 있습니다.

```sh
npm ci
npm test
```

로컬 샘플을 브라우저에서 확인하려면 `npm run preview` 실행 후 `http://127.0.0.1:4173/i/history` 또는 `http://127.0.0.1:4173/i/history/likes`를 엽니다. 테스트용 트윗만 표시하며 실제 X 계정과 연결하지 않습니다. 페이지의 **브라우저 테스트** 버튼으로 현재 너비에 따른 1~4열의 실제 좌표, 내부 래퍼 때문에 발생한 가로 여백, 겹침 여부, 두 페이지의 사이드바 숨김, 동적 추가와 복원 등 19개 항목을 확인합니다.

가상 스크롤 재현은 `http://127.0.0.1:4173/i/history/likes?virtual=1` 또는 북마크 주소 `http://127.0.0.1:4173/i/history?virtual=1`에서 확인합니다. 7개로 시작해서 스크롤에 따라 7개씩 추가로 로딩하며, 화면 밖의 항목은 실제 DOM에서 제거합니다. **브라우저 테스트**로 42개/6페이지 로딩, 위로 돌아왔을 때 열 위치 유지, 늦게 커진 미디어 반영, 원래 클릭 핸들러 유지 등 16개 항목을 확인합니다. 별도 수동 추가 버튼으로 페이지 로딩을 대신하지 않습니다.

1.3.0에서는 자동 테스트 28개를 통과했습니다. 브라우저 너비 1440/1100/800px에서 4/3/2열 전환, 가로 넘침 없음, 일반 목록의 19개 항목과 가상 목록의 16개 항목을 확인했습니다. 가상 목록은 창 크기를 변경한 뒤에도 추가 로딩과 행 정렬을 유지했습니다.

1.3.1에서는 540px 미만 콘텐츠 영역의 1열 표시를 추가했습니다. 자동 테스트 28개를 통과했고, 브라우저 너비 500px에서 일반 목록 19개 항목과 가상 목록 16개 항목, 42개까지 추가 로딩, 1열에서 2열로 돌아갔을 때 정렬 유지와 가로 넘침 없음을 확인했습니다.

1.4.0에서는 그리드 영상의 자동재생 차단을 추가했습니다. 자동 테스트 36개를 통과했습니다. `http://127.0.0.1:4173/i/history/likes?videos=1`은 외부 파일 없이 Canvas 스트림으로 만든 실제 브라우저 영상을 사용합니다. 네 영상의 자동재생 차단, 직접 누르거나 키보드로 실행한 영상만 재생, 일시정지 후 자동 재시도 차단, 그리드 끄기/켜기와 북마크 이동 시 복원을 확인했습니다. 가상 목록의 16개 항목과 42개까지 추가 로딩도 통과했습니다.

1.4.1에서는 반복 재생·정지로 프레임이 빠르게 갱신될 수 있던 방식을 보완했습니다. 페이지 시작 시 `video-play.js`를 MAIN 실행 환경에 등록해 X의 `play()` 호출을 재생 시작 전에 차단합니다. 영상 플레이어의 실제 입력만 DOM의 짧은 수명 표시로 전달하며, 그리드 밖 영상·오디오·다른 경로·그리드 비활성 상태는 원래 `play()`로 처리합니다. 페이지 실행 환경과 기본 콘텐츠 스크립트의 분리는 [Chrome 콘텐츠 스크립트 문서](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)를 따릅니다. **확장 프로그램 업데이트 후 X 탭을 반드시 새로고침해야 시작 시 차단 코드가 적용됩니다.**

자동 테스트 42개를 통과했습니다. 로컬 브라우저에서는 빠른 재시도 1,000회 동안 실제 재생 0회, 일시정지 0회, 영상 시간/프레임 유지, 직접 누른 영상의 1배속 재생, 일시정지 후 재시도 차단, 북마크 이동과 그리드 설정 복원을 확인했습니다. 가상 목록의 16개 항목과 42개까지 추가 로딩도 통과했습니다. 실제 X의 빠른 프레임 갱신 현상은 로그인한 X 탭에서 별도 확인이 필요합니다.

1.5.0에서는 홈·검색 결과·프로필 지원과 다섯 화면별 그리드/기본 목록 설정을 추가했습니다. 1.5.0 당시 기본값은 모두 그리드였으며, 전체 사용 스위치는 각 화면의 선택을 보존합니다. 자동 테스트 51개를 통과했고, 로컬 브라우저에서 홈 일반 목록 19개 항목, 검색·프로필 가상 목록 각각 16개 항목과 42개/6페이지 로딩을 확인했습니다. 홈 영상 테스트에서도 자동 재시도 1,000회 동안 실제 재생·일시정지 0회, 직접 누른 영상만 정상 재생을 확인했습니다. 실제 X의 홈·검색·프로필 동작은 로그인한 X 탭에서 별도 확인이 필요합니다.

영상의 `play` 이벤트는 `play()` 호출과 `autoplay` 속성 모두에서 발생하므로([MDN](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/play_event)), 재생 이벤트 자체를 사용자 요청으로 취급하지 않습니다. 영상 플레이어에서 실제 클릭/키보드 입력을 받은 경우에만 재생을 허용하고, 이외의 `play()`는 브라우저 자동재생 거절과 같은 `NotAllowedError`로 거절합니다([MDN play()](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/play)). 늦게 만들어진 영상 요소도 짧은 시간 동안 같은 플레이어의 직접 입력을 이어받습니다. `autoplay` 속성 등으로 이미 시작된 영상은 한 번 멈추는 보조 처리도 유지합니다.

**로그인한 실제 X의 끝없는 스크롤은 별도 확인이 필요합니다.** 이 버전은 X의 전체 높이와 Y 좌표를 덮어쓰던 이전 방식을 제거했습니다. 다만 X는 내부 DOM 구조와 측정 방식을 바꿀 수 있습니다. 문제가 있으면 팝업에서 그리드를 끄고 페이지를 새로고침해 기본 목록으로 돌아가세요.

코드를 수정한 뒤에는 `chrome://extensions`에서 확장 프로그램의 새로고침 버튼을 누르고 X 탭도 새로고침합니다.

배포용 ZIP은 `python3 tools/package.py`로 만들 수 있습니다. ZIP을 설치할 때는 먼저 압축을 풀고, `manifest.json`이 들어 있는 폴더를 선택합니다.
